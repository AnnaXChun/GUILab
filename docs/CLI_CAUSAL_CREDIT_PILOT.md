# CLI 代码块的反事实信用

**2026-10-22 已执行**：多步 observer/runner、S0 和固定 C 已实现并原生核验；两题各六探针与两对不相关文本控制通过。原预算四次模型请求已用完，四条原文均静态接口拒绝，没有天然候选执行或有效自然 pair。结果、失败、实际成本及完整证据入口见 [本批报告](../reports/CLI_CAUSAL_PILOT_20261022.md)与 `reports/CLI_CAUSAL_STATUS.json`。下一步见 [通用 API 说明对照](CLI_CAUSAL_API_COMPARISON.md)。

本轮设计检验一个具体假设：在多步参数化建模中，从同一工程状态替换一个 CLI 代码块，固定后续执行，再施加公开参数干预，能否识别影响下游结果的构造选择，并形成有用的局部偏好。后续 SFT/RL 使用这种监督，收益需要独立实验。

当前已有事实是一个圆环测量模型配对 Q=1/1、credit=0，以及可信 fixture 和人工重放中的结构故障。测量成功证明执行管线可用。现有 credit 与同一终局检查器的差值一致，尚未产生额外区分能力。研究的下一步是多步构造的局部归因；代码名称、表达式写法或检查器数量都不足以证明方法贡献。

## 要区分的研究问题

| 问题 | 实验观察 | 能支持的结论 |
| --- | --- | --- |
| 参数干预提供了什么信息 | 初始几何通过，保存后参数变化揭示失效 | 工程响应检查比初始几何检查多发现了故障 |
| 反事实执行提供了什么信息 | 相同 S0、相同后续执行，只替换一个代码块，下游结果改变 | 该代码块在这个固定上下文中的局部相对影响 |
| 局部信用有什么用途 | 使用相同响应奖励、相同数据与预算，局部 credit 对照全轨迹奖励 | 训练或数据清洗的收益，需后续测量 |
| 依赖图有什么用途 | 同一探针库、相同上限，按图选探针对照固定或随机选择 | 是否提高故障覆盖率或减少执行成本，另做实验 |

依赖图现在只作记录。FreeCAD OutList 指向对象所依赖的上游对象，查下游影响需反向遍历，不能直接将 OutList 当下游集合。首轮不将图加进 Q，不用图相关术语包装已有差值。

## 固定的小批任务

配置为 `configs/cli_causal_credit_pilot_20261022.json`，其中 `DESIGN_FROZEN_RUNNER_PENDING` 与 null 绑定保留为采样前设计；实际绑定与 S0/C/探针哈希在 run-specific manifest 中冻结，执行状态另存 `reports/CLI_CAUSAL_STATUS.json`。任务来自已有公开 manifest，选择依据是明确尺寸、供应工程及原生依赖链；未读取官方 evaluator 或 reference。两题都转为本研究的 development，原 manifest 的 train 分组保留。它们及相同前置文件来源组不再进入后续 held-out 测试。

| 任务 | 被替换的块 | 固定后续执行 | 验证重点 |
| --- | --- | --- | --- |
| freecad-part-001 | 从供应闭合轮廓创建 12 mm Pad | 重算、保存重开；附加测量审计单列为工程扩展 | Sketch→Pad 的依赖与长度响应 |
| freecad-part-014 | 从供应圆形轮廓创建 10 mm Pad | 创建同心半径 4 mm、深度 6 mm Pocket，再保存重开 | Sketch→Pad→Pocket 的上游影响 |

part-001 是基础结构检查，part-014 是多步归因检查。不得将 part-001 的附加测量审计合并进官方任务成绩。目标对象 Name、Sketch 约束和姿态均取自供应文件的原生观察；不根据 task ID 猜。part-014 的公开圆形由三点给出，不能直接假设圆心在原点或半径为 10 mm。

每题只选一个分叉边界，各采两个独立模型候选。固定 Qwen3.5-122B、相同 prompt、通用 API 说明和采样设置。第二个候选不接收首候选或任何检查反馈。先冻结后续执行 C 和探针，再生成候选；首轮 C 为可信、经原生验证的固定代码，来源写入记录。因此它估计固定续执行中的作用；推广到真实 agent 续执行，需后续捕获完整模型轨迹。

## 执行与信用定义

供应文件来源 SHA 与分叉 S0 SHA 分别记录。准备阶段保存关闭重开 S0，记录原生对象、约束、关系和字节哈希。两个分支在隔离文档、进程、目录及独立副本中开始执行；强 OS sandbox 单独验收。候选原文各执行一次，C 在两分支完全相同。保存后的参数探针只修改参数并 recompute，不重新执行候选或 C。

令 `R0` 为初始公开几何检查，`Rresp` 为保存重开、参数响应、原生有效性和保留检查。原生操作语义按公开要求单列，例如任务明确要求 Part Design Pad 时核对其实现；不得凭 TypeId 给没有此要求的任务加奖励。

```text
S_A = C(A(S0))
S_B = C(B(S0))
delta_block = Rresp(S_A) - Rresp(S_B)
```

这只是 A 相对 B、在该 S0 和 C 下的差值。它不是整条轨迹的可加贡献、完整因果责任或 Shapley value。后续修正可能掩盖前一块的影响，需在不同固定续执行中单独验证；不得通过改 C 让候选通过。

所有 pair 均报告。初始几何相同且 R0 都通过的 pair 另列为“结构区分”子集；初始几何不同的记录仍保留为语义或尺寸差异，不能混称结构增益。未知观测、S0 不一致、续执行接口不兼容、不确定派发或失败导致无可核验 artifact 时，结构质量为 null 并给原因。已知脚本异常与接口不兼容分别记录，不自动设成几何 Q=0。

## 对照与控制

同两条候选、同响应观测，离线计算 first-sample、初始几何 Best-of-2、响应终局 Best-of-2、局部 credit 选择和打乱对应。tie 固定选 A。记录真实模型调用、两路执行和全部探针成本；离线复用算分不等于一次新的独立实验。

响应终局 Best-of-2 与 delta_block 使用同一 Rresp，在单个边界的选择应完全相同。这是核查项，不能报告为局部信用的选择优势。局部归因的对照是“将整个 episode 的响应奖励分配给所有块”：它不能从一个失败终局区分上游 Pad、下游 Pocket 和不相关块。后续训练要比较这种全轨迹奖励与局部偏好，奖励函数保持相同。

新增不相关块负控制：在已成功分支的另一个克隆边界，仅改变独立 AuditNote 文本或无几何影响的显示属性。两控制代码各执行一次，C 保持不变；几何、参数响应及受保护对象应完全一致，credit 应为 0。该控制由可信程序构造，单独标记 synthetic，不算模型 pair。异常时先排查检查器或状态捕获。

首轮每份 artifact 最多六探针：零扰动、两个经原生绑定的参数各 ×0.8/×1.2、不相关参数负控制。具体参数和合法范围在请求前冻结。如果 ±20% 违反公开几何域或造成孔深越界，先收紧范围并记录理由，不能看到模型结果后再选扰动。再测同 S0 的新 clone 时不覆盖旧执行，repeatability 另开无模型审计记录。

## 预算与停止条件

首批最多两题、两个自然模型 pair、四次生成，每次 2048 输出 tokens，共 8192。SDK 重试为 0，请求超时 110 秒，批次总窗口 1800 秒。最多一次准备、四次自然候选派发、四次 synthetic 控制派发，共九次；每份 artifact 的原生参数探针也计入执行和 wall time。默认付费仍为 0，本文件不启动模型请求。

模型服务失败或 unknown usage 后停止后续请求并保留 reservation；非幂等执行不自动重试。批次结束即停，即使全部 tie，也不为了得到非 tie 换账本重复采样。首次采样是可行性检查，不能给总体成功率或可靠性估计。

## 结果如何决定后续投入

| 观察 | 判定与下一步 |
| --- | --- |
| 同 S0、固定 C、保存结构或控制失败 | 修复 observer/执行协议，继续静态与无模型测试 |
| 两个自然 pair 全 tie 或均未知 | 保留结果，诊断候选多样性与目标；暂不扩规模或训练 |
| 只看到初始尺寸差异，没有结构差异 | 只能支持普通候选质量检查，局部结构信用证据不足 |
| 出现初始正确、下游参数响应不同的自然 pair，且控制为 0 | GO 进入更广任务的数据采集；这个小批不证明训练收益 |
| 同样的响应终局检查已经解决全部区分 | 保留该检查器，局部 credit 的价值转由后续归因与训练对照检验 |
| 原生证据可靠、局部标签有覆盖，独立训练条件到位 | 冻结任务组及可训练模型，比较 SFT、相同响应奖励 RL、局部 credit RL |

后续训练不使用这个开发小批和 synthetic 控制作为 held-out 成绩。优先比较错误接受率、局部标签覆盖、同预算任务成功率、原生参数响应通过率和总成本；局部标签单独训练还是 RL 中应用，再根据数据量决定。无需先接 veRL 或下载 122B 权重。

## 本轮实现步骤

设计时的 `scripts/structural_credit_worker.py` 主要观察 primitive，`cli_model_pair.py` 只允许写 Torus 测量属性。本轮新增 `scripts/cli_causal_worker.py`、`scripts/run_cli_causal_credit.py`、`cad_cf/cli_causal_credit.py`，按以下步骤完成适配，历史设计保留：

1. 从 pinned 供应文件核对上述来源 SHA，扩展原生 observer 以覆盖 Sketch 几何/约束、Body.Tip、Pad.Profile、Pocket.Profile/BaseFeature 和表达式。先通过真实文件的保存重开一致性检查。
2. 冻结模型构造块的接口契约。两候选共享输出对象及关系要求，保留构造实现自由；模型原文经范围检查，避免把接口强制成唯一已知答案。
3. 用实际 S0 验证固定 C 和六探针库，写 run-specific immutable manifest。所有 null 的对象绑定、S0、C、探针哈希必须补齐并核验；否则拒绝模型请求。
4. 先跑无模型 clone/负控制 smoke，再发最多四次新采样。复用模型预算、一次派发、响应封装和证据归档模块；旧账本、旧源码快照及官方 baseline 保留。

新任务通过专用 runner 执行，不能把这份配置传给只支持 Torus 的旧 runner。缺供应工程或原生接口时写 `BLOCKED_BY_ENV`；缺模型配置时写 `BLOCKED_BY_CREDENTIALS`。本轮实际模型请求为 4，native 派发累计为 10，其中前置调试与 uncertain 失败单列；详细成本以本批报告为准。四次账本已结束，不直接重跑已消费配置。本方案原生部分通过，天然结构信用和训练仍 NO-GO。
