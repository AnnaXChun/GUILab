# 先验证通用 API 说明

part-001/014 的可信原生管线与控制已通过，四条自然模型候选均静态接口拒绝，原生质量 unknown。下一批先检验通用 API 说明能否让模型进入原生执行，再观察参数响应和局部信用。历史四条响应继续保留；本文件定义待执行对照，本轮新增模型调用为 0。

## 两组共享什么

使用相同 Qwen3.5-122B 服务、公开任务、原生版本、S0、固定后续代码 C、探针库、输出解析和范围检查。S0/C/探针须在新请求前冻结并核验哈希；新主机先准备自己的原生状态，仓库证据中的绝对路径只作 provenance。已发布的原生文件只保留本地，不从摘要伪造 S0。

原说明组复用本批 `cad_cf.cli_causal_credit.messages` 的接口说明。通用 API 组只增加经独立原生探针核验的说明：

- 在所属 Body 中创建 Part Design feature 的公开方式，以及当前范围检查允许的调用形式。
- Pad.Profile 的公开对象关系和实际属性类型；Base、BaseFeature 与 Profile 的用途按运行版本的 introspection 记录。
- Length 的长度单位及合法赋值形式。

独立 API 探针使用另建的简单测试文档；不把两题的完整构造代码、可信 C、目标几何计算、verifier 结果或官方 evaluator 交给模型。API 说明不修改任务要求。若冻结的范围检查遗漏一种有证据支持的公开接口，先对两组同时做最小适配、补失败回归，再冻结请求；历史拒绝结果不回写。

## 预算与独立性

计划两题 × 每组两个独立候选 × 两组，共 8 次新请求，每组 4 次；每次最多 2048 输出 tokens，共 16384，SDK 重试为 0。两个候选使用相同 messages，彼此不接触响应或反馈。组别顺序在请求前平衡冻结，不能用这轮历史 4 次拒绝代替新的原说明对照。

这 8 次是下一批计划，尚未执行，也不改变已耗尽的四次账本。执行前需将通用说明、源文件、模型设置、顺序和硬额度写入新的 immutable manifest 和独立账本，预算由新批次约束；默认 `ENABLE_PAID_RUNS=0`。服务错误或 unknown usage 后停止后续请求，不确定 /execute 隔离且不重发。天然候选执行只运行原文一次；两路 C 相同，参数探针只 recompute，不能通过修改 C 或候选修补失败。

## 记录与判断

每组分别报告接口接受数/4、原生完成数/4、有效 pair 数/2、初始几何通过数、参数响应通过数、tie/invalid 和信用分布。接口拒绝用 unknown 原生质量，已知执行异常单列；接受率分母保留全部请求。报告调用/tokens、准备、控制、两路执行与探针的总成本，不估算服务未知价格。

可信管线通过支持继续这一小批可行性对照。若原生完成后出现初始几何同样通过、参数响应不同的自然 pair，可进入更广的局部标签采集；若仍全拒绝/unknown 或全 tie，保留结果后诊断，不为非 tie 继续重复开账本。两题均为 development，不报告 held-out 成绩或总体成功率。

单个分叉的 `delta_block` 与相同 Rresp 的终局 Best-of-2 选择应等价。API 说明收益支持执行可行性；方法收益仍需真实多步轨迹上的局部归因覆盖，以及相同响应奖励、相同数据/预算下的全轨迹 RL 与局部 credit 对照。当前不启动训练、下载权重或接 veRL。
