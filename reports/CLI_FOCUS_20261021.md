2026-10-21 用户要求继续 CLI，后续围绕 CLI 做 RL、数据清洗和成功率改进，停止 GUI 研究。原 SPEC 作为历史保留，新方向见 `docs/CLI_RESEARCH_PLAN.md`。旧 ACTC 的 GUI/API 配对门槛不再作为 CLI 研发前置，也不改判为通过。

现有证据已确认：sketch-061、sketch-062 官方评分通过；part-076 的后续尝试仍有原生状态或建模过程问题；part-077 最新一次实际 8 轮，以 API 错误结束且无文件。此前“CLI 无法创建参数化结构”“三棱柱已执行 24 轮”的表述撤回。FreeCAD API 能建立原生草图、约束和特征树，失败要按实际轨迹归因。

已先完成小批选择、共享预算与禁用 GUI 的测试，冻结代码和配置，再启动真实模型。结果、原生审计、清洗统计和 GO/NO-GO 见下文。

## GO / NO-GO

CLI 采集、少量原生审计、清洗和公开奖励 smoke：GO。继续增加任务家族、固定分组并做等预算对照：GO。真实 SFT/RL 训练和独立测试集提升结论：NO-GO；当前只有 3 条通过的示例，可训练权重、训练 GPU 和训练框架尚未配置验收。托管 API 的推理成功不等于具备训练环境。

下一步先冻结更多 CLI 开发任务与未使用的验证/测试家族，比较原 prompt 和通用 FreeCAD API 使用说明，优先解决 attachment、无效 feature 和扁平 Shape。随后扩充原生质量与公开任务目标奖励，积累足够训练数据，再执行小模型 SFT/RL。原论文 GUI-only 全量复现、ACTC 路由收益和总体成功率仍未完成，本轮不作这些效果声明。所有模型与审计 VM 均已停止。
